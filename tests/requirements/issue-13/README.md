# #13 요구별 보존 검증 기준표 v3 — 독립 재검토 대기

이 문서는 [#13](https://github.com/SJO1231/G2B-Helper/issues/13)의 검증 **기준표**다. 검사 코드는 작성하지 않았고 검사 실행 결과도 없다. 모든 판정 칸은 `미실행`이다. 기준표 작성은 요구 충족·검증 완료·사용자 수용을 뜻하지 않는다.

v2 독립 재검토가 구현 준비로 본 범위와, v3에서 바뀌어 다시 검토받아야 할 범위는 §11에 나눠 적었다. 구현 준비 판정은 구현 승인이 아니며, 검사 코드는 사용자 승인 뒤에만 구현한다. `[v3 …]` 표시는 v3에서 바뀐 기준이다. 그중 `[v3 최신 요구]`는 2026-10-05 사용자 최신 요구(S-N13R3)로 바뀐 기준이다.

## 2. 판정 규칙

- **판정 값**: `충족`, `미충족`, `미검증`(사유를 함께 기록: 실행 오류·준비 실패·어댑터 불일치·대상 0건·자료 없음·증인 불성립·관측 경로 없음), `조건부(관측 기준선)`, `근거 있는 비해당`, `미확정(관측만)`.
  - `조건부(관측 기준선)`는 독립 기대 표시를 정할 수 없는 대상(F44)에서, 관측한 처음 표시를 기준으로 본 관계 판정이다.
  - `조건부(대표 규칙 미확정)` `[v3 최신 요구]`는 Q4(대표 품목 선정) 답 전에 A1-s1·A1-s6에서 "묶음 안 어느 한 품목과 맞음"까지만 확인된 상태다.
  - 미검증·조건부·미확정은 통과 수에 넣지 않고, 해당 요구나 #13 완료의 근거로 쓰지 않는다.
- **계산 개념 구분**
  - Number 변환: 문자열을 IEEE 754 배정밀도로 바꾸는 것. 2^53(9007199254740992)을 넘으면 정수 부분도 가장 가까운 표현값으로 바뀐다.
  - 정확한 소수 계산: 10진 문자열·BigInt로 손실 없이 계산하는 것.
  - 표시 반올림: 정확한 값을 N자리로 반올림하는 것. 동률(.5) 규칙은 미확정이다.
  - 기대값은 정확한 소수 계산과 표시 반올림으로만 정하고, 동률 규칙에 따라 결과가 갈리는 사례는 쓰지 않는다. Number 경로의 결과는 어떤 사례가 Number 손실을 구별하는지 표시하는 데만 쓴다.
- **증인 전제**: 판정마다 "정상이면 반드시 관측되는 차이"가 성립하는지 먼저 확인한다(예: 검색 결과가 비어 있지 않고 필터가 실제로 행을 줄임). 증인이 성립하지 않으면 그 판정은 `미검증(증인 불성립)`이며 통과가 아니다. 실행마다 증인 성립 여부를 기록한다.
- **관측 경로**: 동작 판정은 대상별로 선언한 관측 경로(DOM 상태, 화면·모드, 다운로드 이벤트, 대상의 요청 기록)로 확인한다. 컨트롤 자체의 상태 변화(체크 표시·눌림 상태·안내 문구)는 효과로 인정하지 않는다. 관측 경로가 없는 대상은 `미검증(관측 경로 없음)`이다. 합성 시안의 관측은 실제 호스트·나라장터 실행과 구분해 `합성 관측`으로 표기한다.
- **저장소 구분**: 원천(원본 자료), 작업(편집·사용자 열), 표시(화면)를 구분한다. 어댑터는 각 판정이 어느 저장소를 읽는지 선언한다. 대상이 저장소를 분리하지 않으면 해당 판정은 `미검증(저장소 분리 불가)`로 기록한다.
- **공통 판정 함수**: 정상 fixture·결함 주입 사본·F44가 같은 판정 함수를 쓴다. 대상별로 다른 것은 요소 찾기·상태 읽기 어댑터뿐이며, 그 차이를 결과에 공개한다. 기대값과 검사 의미는 대상별로 바꾸지 않는다.
- **요소 찾기**: 가능하면 접근 가능한 이름(텍스트·aria-label)으로 찾는다. 요구된 수단이 없으면 `미충족(부재)`, 있는데 찾는 방식이 실패하면 `미검증(어댑터 실패)`로 구분한다.
- **기대값**: 사례별 고정 기대값을 이 문서에 직접 적는다. 계산은 정확한 소수 계산만 쓰고 Number를 쓰지 않는다.
- **결함 주입 결과**: §5의 결과 분류(검출 성공·검출 실패·판정 불가·판정 대상 아님)를 따른다 `[v3 F6]`. (v2 문구: "§5의 결과 상태 6종을 따른다.")
- **실제 결함 처리**: F44의 알려진 결함은 실패로 그대로 기록한다. 시안·제품을 고치거나 fixture·기대값을 완화하지 않는다.

### O-1 오라클 정밀도

- 기대값은 R1·P1 고정 사례표에 직접 적은 문자열이다.
- 정정: v1의 "`Number('9007199254740993.25')`가 `9007199254740992`가 됨"은 틀렸다. 실제 결과는 `9007199254740994`다. 2^53 근처의 배정밀도 표현 간격은 2라서, `…993.25`는 `…992`까지 1.25, `…994`까지 0.75 떨어져 있고 더 가까운 `…994`가 된다. 검토자 수치를 아래 임시 계산으로 독립 확인했다.
- 검산 함수(BigInt·문자열 기반)는 모든 고정 사례를 재현하는지 자체 검사한다. 검산 함수가 고정값과 다르면 검사기 결함으로 보고하며, 고정값을 고쳐 맞추지 않는다.
- **임시 계산(v2 작성 중, 검사 실행 아님)**: 저장소 스크립트·제품 코드·설치·네트워크 없이, Node v22.22.0 내장 `Number`·`toFixed`·`BigInt`와 Python 3.11.15 표준 `decimal`만 썼다. 스크립트는 작성자 임시 경로에 두었고 저장소에 넣지 않았다.

  | 원값 | 자릿수 | `String(Number)` | Number 경로 `toFixed` | 정확(올림) | 정확(짝수) | 버림 |
  |---|---|---|---|---|---|---|
  | `9007199254740993.25` | 2 | `9007199254740994` | `9007199254740994.00` | `9007199254740993.25` | 같음 | 같음 |
  | `9007199254740993.25` | 0 | `9007199254740994` | `9007199254740994` | `9007199254740993` | 같음 | 같음 |
  | `35608652.5` | 1 | `35608652.5` | `35608652.5` | `35608652.5` | 같음 | 같음 |
  | `35608652.5` | 0 | `35608652.5` | `35608653` | `35608653` | `35608652` | `35608652` |
  | `9007199254740993.75` | 0 | `9007199254740994` | `9007199254740994` | `9007199254740994` | 같음 | `9007199254740993` |
  | `0.26` | 1 | `0.26` | `0.3` | `0.3` | 같음 | `0.2` |
  | `0.123456789012345678901` | 20 | `0.12345678901234568` | `0.12345678901234567737` | `0.12345678901234567890` | 같음 | 같음 |
  | `12345678901234567890.125` | 3 | `12345678901234567000` | `12345678901234567168.000` | `12345678901234567890.125` | 같음 | 같음 |

  - 보조 확인: `BigInt(Number('9007199254740993.25'))` = `9007199254740994`, `BigInt(Number('9007199254740993'))` = `9007199254740992`, `BigInt(Number('12345678901234567890.125'))` = `12345678901234567168`.

## 5. 정상 fixture·결함 주입 명세

- **정상 fixture**: `fixtures/`의 합성 HTML 1개로, 요구대로 동작하도록 직접 작성하며 F44 코드를 복사하지 않는다.
  - 증인 자료를 모두 포함한다: R1 고정 사례 값, R2 D1·D2, 전체 빈 열·빈 원본 표·미등록 열·pointInfo, M04 범주 값, 관련 메모·일정, A1 증인 묶음 W1~W7(v2: A1 정상 증인 품명) `[v3 최신 요구]`, B1 S0 자료.
  - 처음 표시 집합은 고정한다(R2-init·A4-c 기대값).
  - 상태 변경은 실제 DOM 이벤트로만 한다. 검사 전용 통과 도우미나 미리 고정한 통과 상태를 두지 않는다.
  - 요청 기록(합성 관측 경로)은 R4의 조회·엑셀·건수·런처 동작에만 쓴다.
  - 정상 fixture의 필수 판정이 하나라도 충족이 아니면 검사기 또는 fixture 결함으로 보고한다. 기대값이나 fixture를 고쳐 통과시키지 않고, 원인을 기록한 뒤 재검토를 받는다.
- **결함 주입 사본**: 실행할 때 정상 fixture를 OS 임시 경로에 복사하고, 각 요구의 M-* 결함을 하나씩 넣는다. 사본마다 다음을 기록한다.
  - 주입 위치: fixture 안 표식 블록 ID
  - 주입 적용 증거: 주입 전후 SHA256과 표식 블록 diff
  - 의도 요구 ID
  - 실패해야 할 판정 ID
- **결과 분류** `[v3 F6]`: 사용자 지시(S-N13R3의 결함 주입 결과 부분)와 V2-REVIEW F6에 따라 v2의 결과 상태 6종을 아래 4종으로 바꿨다. v2 표는 아래 접힘 영역에 보존했다.
  - 먼저 확인하는 조건
    - (가) 주입 적용 증거가 있다(주입 전후 SHA256과 표식 블록 diff).
    - (나) 같은 실행 조건의 정상 fixture(기준 실행)에서 지정 판정이 `충족`이고 증인이 성립했다.
    - (다) 주입 사본에서 화면이 열렸고, 지정 판정의 관측 대상(요소·목록·표)을 읽었다.
  - 검사기는 지정 판정에서 찾은 차이를 첫 차이에서 멈추지 않고 모두 원인 목록으로 출력한다. 원인 목록이 끝까지 출력되지 않으면 "출력 불완전"으로 기록한다.

  | 분류 | 조건 | 집계 |
  |---|---|---|
  | 검출 성공 | (가)(나)(다)가 성립하고, 지정 판정이 `미충족`이거나 근거 연결·단위 보고 같은 보고 검사의 지정 목록에 항목이 나왔으며, 출력된 원인이 주입 결함과 일치한다(같은 요소·같은 값). 예: M-R4-8은 근거 미확인 목록에 주입한 버튼의 이름·위치가 그대로 나와야 한다 | 검출 성공 |
  | 검출 실패 | (가)(나)(다)가 성립했는데 다음 중 하나다. ① 지정 판정이 `충족`이다. ② 지정 목록이 정상 출력됐는데 주입 항목이 없다(M-R4-8에서 다른 버튼만 나온 경우 포함). ③ 지정 판정이 `미충족`이고 원인 목록이 완전하게 출력됐는데 주입 결함이 원인에 없다. ④ 다른 판정만 실패했다 | 검출 실패. 검사기 보완 대상 |
  | 판정 불가 | 다음 중 하나다. (가) 불성립(주입 미적용). (나) 불성립(기준 실행에서 지정 판정이 이미 충족이 아님. 검사기·fixture 결함으로 따로 보고). (다) 불성립(화면이 안 열림, 대상 0건, 관측 경로 없음, 어댑터·파싱·브라우저·준비 오류, 시간 초과). 지정 판정이 `미검증`(증인 불성립 포함, 아래 예외 제외). 지정 판정이 `미충족`인데 원인 목록이 출력 불완전이라 주입 결함을 확인했는지 알 수 없음 | 성공도 실패도 아니다. 통과로 세지 않고 원인을 기록한 뒤 재실행한다 |
  | 판정 대상 아님 | 미확정(관측만) 항목에 대한 주입 | 결함 주입을 만들지 않는다 |

  - 전제를 깨는 주입의 예외: M-R2-7처럼 주입 효과가 곧 증인 전제의 불성립이면, 지정 판정을 전제 확인 판정(R2-0)으로 둔다. 정상 fixture에서는 전제가 성립했고, 주입 사본의 전제 확인 출력이 주입 효과(관측 B 공집합)를 원인으로 기록할 때만 검출 성공이다. 그 밖의 증인 불성립은 판정 불가다.
  - 주입 결함과 관계없는 이유로 실패한 결과는 그 결함의 검출 성공으로 세지 않는다(검출 실패 ③④ 또는 판정 불가). 다른 요구가 함께 실패하는 것은 허용하되, 지정 판정의 성공 여부는 위 조건으로만 정한다.
  - 보고 검사(R4-c 근거 연결, A1-u 단위 확인)의 출력은 제품 충족 판정이 아니다. M-R4-8에서 검출 성공이어도 제품 판정 R4는 `미검증(승인 미확인)`으로 남는다.
  - v2 상태와의 대응: 검출 → 검출 성공(원인 일치·기준 실행 조건 명시), 전제 불성립 검출 → 위 예외를 만족하면 검출 성공·아니면 판정 불가, 생존 → 검출 실패, 오류(미판정) → 판정 불가, 근거 확인 결과 → 목록 등장이면 검출 성공·정상 출력 목록에 없으면 검출 실패·목록 미출력이면 판정 불가, 판정 대상 아님 → 유지.
  - 주입 사본은 저장소에 쓰지 않는다.
