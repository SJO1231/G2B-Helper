# 검증 기록

확인일: 2026-09-30  
대상: 이 파일 묶음에 새로 작성한 지침·Skill·안내·양식과 원본 보존본

## 실제 확인한 범위

| 항목 | 결과 | 근거와 범위 |
| --- | --- | --- |
| 입력 자료 원본 유지 | 확인 | 제공된 5개 파일의 현재 SHA-256이 작성 전 기록과 일치 |
| CLAUDE.md 원본 보존 | 확인 | references/input-claude.md와 제공 원본의 전체 바이트가 일치 |
| 핵심 네 원칙 | 문서 대조 확인 | AGENTS.md의 네 절과 원본을 대조; 설계·출처 문서에 대응 관계 기록 |
| 공통 규칙 관리 | 확인 | AGENTS.md가 공통 지침을 소유하고 CLAUDE.md에 @AGENTS.md import 존재 |
| 여섯 Skill의 기본 형식 | 자체 정적 검사 6/6 통과 | 아래에 설명한 제한된 메타데이터 검사 사용 |
| 프로젝트별 제도 혼입 | 자체 문서 검토 | 특정 모델·명령·브랜치·Issue 생성·고정 검증 횟수를 공통 의무로 지정하지 않음 |
| 작은 작업의 부담 | 자체 문서 검토 | 별도 계획 파일·장기 기록·POC·위임을 모든 작업에 요구하지 않음 |
| 원천과 새 작성물 구별 | 확인 | 여섯 Skill을 기존 저장소의 공식 Skill이나 이미 설치된 기능으로 표시하지 않음 |

입력 파일별 SHA-256은 설계·출처 문서에 기록했다.
메타데이터 검사는 name과 description만 사용하는 현재 파일 형식에 한정된다.

## Skill 형식 검사 상세

| Skill | 검사 결과 |
| --- | --- |
| focused-plan | 통과 |
| root-cause-fix | 통과 |
| verify-change | 통과 |
| session-handoff | 통과 |
| review-boundaries | 통과 |
| delegate-bounded-task | 통과 |

직접 실행한 검사는 다음을 확인했다.

- UTF-8 읽기 및 깨진 대체 문자 부재
- frontmatter 경계와 name·description의 존재·중복 부재
- 현재 사용한 단일행 YAML 일반 문자열의 제한된 문법
- 이름의 소문자·숫자·하이픈 형식, 길이, 폴더명 일치
- 설명의 비어 있지 않음·길이·금지 구분 문자
- Skill 본문의 존재와 미완성 TODO 부재
- AGENTS.md·사용 안내의 Skill 이름 연결
- 파일명의 대소문자 충돌 부재와 내부 Markdown 링크의 파일 존재·대소문자·패키지 내부 경로

기본 제공 quick_validate.py도 실행을 시도했으나 Python 환경에 PyYAML이 없어 시작하지 못했다.
작업용 폴더에만 의존성을 준비하는 시도도 네트워크 제한으로 완료되지 않았다.
따라서 **기본 제공 검사기 통과 또는 완전한 YAML 파서 검증이라고 주장하지 않는다.**
대신 위의 한정된 정적 검사와 본문 검토를 수행했다. 전역 Python 환경을 변경하지 않았다.

## 문서상 상황 점검

다음은 작성자가 조건과 지침의 일관성을 읽어 확인한 것이다.
Agent를 실제 실행한 행동 평가나 독립 검토 결과가 아니다.

| 상황 | 문서가 요구하는 행동 | 확인 위치 |
| --- | --- | --- |
| 오타 한 곳 수정 | 최소 수정과 결과 확인; 별도 계획·위임 생략 | AGENTS 도입부, README |
| 결과를 바꾸는 두 가지 해석 | 차이와 필요한 질문을 밝히고 의존 구현 대기 | AGENTS §1, focused-plan |
| 기존 미커밋 변경 존재 | 범위·diff 확인 후 보존 | AGENTS §3, session-handoff |
| 검토만 요청 | 제품 코드 수정 없이 관측 근거 보고 | verify-change, review-boundaries |
| 준비 오류로 테스트 실패 | 버그 재현 또는 검증 통과로 세지 않음 | root-cause-fix, verify-change |
| 렌더 환경이 없음 | 실제 화면 확인을 미검증으로 표시 | verify-change |
| 검사기 변경 | 정상 사례·실제 위반·관련 우회 반례 확인 | review-boundaries |
| 위임 도구·허가·분리 이득 없음 | 직접 또는 순차 수행; 독립 검토로 보고하지 않음 | delegate-bounded-task |
| 과거 기록과 현재 상태 불일치 | 전제·상태 재확인; 과거 제안과 현재 승인을 구별 | session-handoff |

## 아직 확인하지 않은 범위

- 실제 프로젝트의 기존 AGENTS.md·CLAUDE.md와 병합했을 때의 충돌
- Claude Code에서의 import와 /Skill 호출
- Codex에서의 .agents/skills 탐색과 $Skill 호출
- 자연어 요청에 따른 Skill 자동 선택의 정확도
- 실제 코드 과업에서의 결과 품질과 반복적인 행동 평가
- 다른 Agent가 수행하는 독립 검토

따라서 현재 상태는 **사용 가능한 파일 작성과 한정된 정적 확인 완료**이며,
특정 프로젝트에 설치·등록되었거나 실제 작업 성능이 입증됐다는 뜻은 아니다.
실제 적용 후에는 README의 첫 적용 확인 절차를 수행한다.
