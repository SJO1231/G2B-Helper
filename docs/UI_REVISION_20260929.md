## 구현을 위한 설계 선택

- 메모 자동 저장은 입력 후 550ms debounce, IME 조합 중 저장 지연, 쓰기 직렬화, SQL CAS를 사용한다. 응답 유실 시 같은 요청 ID·동결된 요청을 재사용한다. 이는 사용자 원문이 아닌 구현 선택이다.
- 색상·휴지통·생성/수정 시각은 기존 메모 논리 테이블의 열로 관리한다. 신규 업무 테이블이나 DB 마이그레이션을 임의 추가하지 않는다.
- 메모 화면 키는 `[URL, areaCd, depth1, depth2]`이며 기존 키와의 호환을 유지한다. 동적 화면 ID를 새 키에 넣지 않는다.
- 런처 저장 성공과 목록 갱신 성공은 별도 결과로 처리한다. 저장 이후 갱신 실패는 이미 저장되었음을 표시한다.
- 런처 일반 삭제는 기존 확인 절차를 유지한다. 메모의 휴지통 요구를 모든 테이블의 삭제 정책으로 임의 확대하지 않는다.
