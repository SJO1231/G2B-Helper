## 구현 순서와 검수

1. **P0 창/배치/DB 면적**: OS 새창을 페이지 내 창으로 교체. 위젯 네 탭 유지, 런처/DB 진입점에서 리모컨 근처 창 열기, 일반창 이동·메모 크기 조절/여러 창/닫기/재열기. DB 목적뷰는 목록 약180~210px, 나머지 면적을 grid에 배정. 백그라운드 자동과 SQL 원천 탭 고정은 회귀 검수.
2. **P0 업무 설명/건수**: 원본 빠른 버튼·건수 목록+직접입력·적용/조회 명칭 복원. 연간이 아닌 범위 첫 클릭의 실제 결과를 안내. 요소를 찾지 못하면 구체 원인과 선택 경로 표시.
3. **P1 런처/메모**: 목록 버튼과 +/⋮, 설명·순서·화면범위, Keep 카드/정렬/그룹/색·핀·화면메모를 복원. 기존 SQL에 없는 필드는 추가 정의를 명시하고 원본 DB를 직접 가져왔다고 주장하지 않음.
4. **P1 관리 창**: 원본 사전/수집 구획은 기능 의미를 확인하는 근거로 사용하며 반드시 같은 개수의 탭으로 복제하지 않는다. 백업/복원과 필요한 설명 접근을 유지한다. 실제 구현 안 된 이벤트 유형/직링크는 미구현으로 표시하고 빈 성공 UI를 만들지 않음.

정적 감사만 수행했다. 원본 bookmarklet을 실행하거나 원본 IndexedDB를 읽고 쓰지 않았다. 원본 IndexedDB/localStorage를 활성 저장소로 되살리지 않는다. 새로운 창/DB 수정의 타입검사·단위검사·브라우저 인수검사 결과는 STATUS/TEST_REPORT에 별도로 기록한다.

## 최종 시각 확인
DB, Import, 필터, 위젯, 사전, 메모·스티커 화면을 실제 브라우저 PNG로 확인했다. 스티커는 기본 도구창과 달리 옅은 노란 배경으로 통일하고 중복 연결 문구를 숨겼다(오류는 유지). Impeccable 정적 검사는 filter-group의 2px 왼쪽 선 1건을 감지했다. 이는 카드 장식이 아니라 AND/OR 조건의 계층 구분이므로 유지했다. 감지 결과를 사용자 만족이나 실제 나라장터 검증으로 간주하지 않는다.
