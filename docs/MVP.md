# G2B Helper — 현재 MVP 기준 (2026-10-02)

최신 근거는 사용자 첨부 `0b2ba2aa-4f8c-4620-ad4c-8d580ef6dc26/붙여넣은 텍스트.txt`와 후속 답변이다. 기존 전체 제품 요구는 PRODUCT.md에 보존하며 이번 단계에서 삭제하지 않는다. 승인된 하네스는 P00, 현재 MVP 작업은 M01에 기록한다.

## 확정과 정정

- Chrome/Edge MV3, 작은 이동형 리모컨·원형 접기·페이지 안 Grid. 닫기는 종료, 확장 아이콘으로 재실행.
- 수동 추출은 현재 로딩 자료를 임시 Grid로만 표시한다. 수집은 지정 URL+areaCd+depth1+depth2(+존재하는 depth3)와 업무키를 검사한 뒤 비교·저장한다.
- 후속 사용자 지시: `참고자료/js.txt`의 WebSquare gridView → DataList.getAllJSON 방식이 추출 기준이다. 기본 추출 표는 `tables`만, 설정의 전체/테이블 선택으로 `pointInfo`도 표시할 수 있다. pointInfo는 표시 설정과 무관하게 원본과 화면 판별에 유지한다. 빈 표도 삭제하지 않는다.
- SQLite Gateway 사용은 사용자 답변으로 재확정했다. 첨부의 IndexedDB 폴더/흐름과 SQLite 제외 문구는 이번 구현에서 적용하지 않는다. 브라우저 데이터 저장소로 우회하지 않는다.
- 상세 중복 규칙을 따른다: 신규 저장, 동일 유지, 기존 빈값 자동 보충, 충돌은 간단한 필드 선택창. 영구 변경이력/복잡한 DIFF 시스템은 보류한다.
  - 2026-10-09 지시 3번으로 대체(#43, 사용자 원문 아님): 충돌은 묻지 않고 화면 값으로 반영하며, 확인 버튼 없는 알림(DB 화면 상태줄, 문서 생성 창)으로 바뀐 칸만 알린다. 화면 값이 비어 있으면 DB 값을 지우지 않는다. 하위 표는 다르면 화면 표로 통째로 바꾸고, 화면 표가 비어 있으면 그대로 둔다(지금까지의 “추가만 하고 지우지 않음”을 대체). 화면에 아예 없는 표도 그대로 두는 것은 AI 해석이다.
- SON 원문은 문맥상 JSON 원문으로 해석한다. 원천 key 변경 없이 표시명만 사전에 저장한다. 사용자 열은 원본과 별도 저장한다.
- 저장 안전성을 위한 구현 기본값: 사용자 열 삭제는 정의만 제거하고 기존 저장값을 보존한다. 필터 밖 행에서 삭제한 정의를 다시 생성하지 않는다. 영구 삭제·삭제한 열 복원 UI는 보류한다. 이는 사용자 원문의 확정 동작과 구분하는 설계 기본값이다.
- 후속 확정: 설정에서 다섯 실행 단축키를 지정(수집 Alt+Shift+S, 문서 연결 Alt+Shift+D 기본), 리모컨은 ±1년 버튼만 두고 Grid는 날짜 구간과 ±1년 필터를 함께 둔다. 돈·날짜·텍스트 열 타입은 원값을 바꾸지 않고 표시·입력 검사를 담당한다.
- 계약만: 종결 사용자 체크열/독립 필터, 지정일, 지체일수(지정일−납품기한), 종결금액, 미종결금액(계약금액−종결금액), 선금보증기한/금액. 파생 두 열은 읽기 계산값이며 빈 종결금액은 계산에서 0으로 해석하고 입력 자체는 빈값을 유지한다. 전 업무 공통으로 사용자 열 숨김/해제 버튼을 제공한다.
- 자동수집·자동 클릭/탐색 기능, 문서/HWPX, 탐색기, 메모·일정, AI/Jev, 복잡한 관계·정규화는 제품에서 제외한다. Playwright는 제품에 넣지 않고 개발 검증에 사용 가능하다는 후속 사용자 정정을 따른다. 수동으로 누른 업무 보조 버튼만 페이지에 명령을 전달한다.

2026-10-09 지시 5번(#45, 사용자 원문 아님): Helper가 만드는 열은 Native가 읽을 때 만들고 저장하지 않는다(읽기 전용). 입찰 ‘업종제한’은 자격제한 표에서 묶음(lmtGupSqno)이 처음 나오는 순서와 줄 순서대로 “업종명(코드)”를 “와 ”로 잇고(원문 예의 띄어쓰기), 코드가 비면 업종명만 쓴다. 묶음 순서를 나오는 순서로 본 것은 AI 해석이다. 자격제한 칸은 이 문장을 보이고, 누르면 표가 뜬다. 수요기관 담당자 열은 수요기관 표 첫 줄에서 입찰 deptNm·picNm·tlphNo·eml·dmstPicId, 접수 deptNm·eml·dmstPicId를 원래 키 이름으로 올리며, 메인에 같은 키가 있으면 올리지 않는다. lcnsLmtYn에는 라벨 ‘업종제한 여부’를 붙였다(라벨 문구는 AI가 정함, DB 구조 버전 4, 사용자가 이미 붙인 라벨은 그대로).

## Studio lite 생성 연결 (2026-10-03 사용자 승인)

이 절은 앞의 문서/HWPX 제외 범위 중 지정 서식 생성 연결만 대체한다. 업무 DB와 선택 자료는 Helper가 소유하고, 서식·원천 키 Column 매핑·문구 조건·파일 생성은 Studio lite가 소유한다. Helper가 DB에 먼저 저장하도록 강제하거나 Studio가 Helper DB를 직접 쓰지 않는다. 개인 분석기, DocWeave, 신규 수집 표, 관계 편집, 트레이·전역 단축키, 설치 통합은 이번에 추가하지 않는다.

Studio lite에서 저장한 프로젝트 revision과 출력 폴더를 생성 프로필 ID에 연결한다. Helper의 문서 연결 설정은 업무별 프로필 ID와 업무·서식별 필드 연결(서식 필드 이름 → 원천 키)을 저장한다. 문서 매핑은 저장된 연결, 같은 이름의 원천 키, 하나로 맞는 표시명 순으로 찾는다(2026-10-07 사용자 승인으로 수정, 아래 "문서 생성 연결" 절). 리모컨 문서는 현재 화면 인식 → 간단한 자료 선택창 → 연결된 서식으로 파일 저장이다. 화면 규칙/업무키로 인식한 자료만 후보로 쓰고 하위 표·출처를 보존한다. 매칭 자료가 없으면 DB로 연결하며 읽기 오류는 자료 없음과 구분해 알린다. DB나 추출 표에서 선택한 행의 생성도 같은 선택창을 사용한다. 선택창은 자료별 체크와 이미 연결된 서식을 표시하며 100건 초과 후보는 자동 선택하지 않는다. 문구 조건은 기존 Studio 서식이 소유하고 별도의 임의 조건 편집기는 추가하지 않는다. 정상 연결이면 서식 선택창·Studio 제작기를 매번 열지 않는다. 연결이 없을 때만 서식을 지정하며 누락·충돌·지원하지 않는 자료는 항목별 보완 사유로 표시한다.

첫 연결은 1~100개 선택 행과 단일 값 서식이다. 원천 필드·사용자 값·출처·업무 식별값을 구분해서 전달하고 선행 0·정밀 금액 문자열·0·false·빈값을 유지한다. 빈 하위 표는 허용하고 실제 하위 행이나 중첩 값은 누락시키지 않고 생성 보완 대상으로 돌린다. Studio의 기존 money 형식이 정확히 처리할 수 없는 소수·큰 금액은 문자 매핑을 사용하며 안전한 정수 원 금액만 money로 허용한다. Helper 표의 읽기 계산 열은 원천 필드에 섞지 않는다.

Native는 고정 loopback 주소의 Studio 경로로 요청 ID·출처·프로필 ID·자료를 보내며, Studio는 프로젝트/출력 계획과 항목별 결과를 저장한다. 같은 요청의 재시도는 같은 파일을 확인하고 다른 입력에 같은 ID를 재사용하면 거절한다. 기존 파일은 같은 해시인 경우만 재사용하며 다른 파일은 덮어쓰지 않는다. 파일 저장 완료·보완 필요·실패를 구분하고 자동 열기/인쇄는 하지 않는다. 진행 중에는 생성창 닫기를 막고, 통신 결과를 확인하지 못하면 열린 Helper 화면에서 같은 요청으로 재확인한다.

Native는 생성 응답의 항목 수·번호·상태와 성공 파일 경로, 전체 상태 및 요약 건수의 일치를 확인한다. 같은 항목 상태만 있으면 전체 상태도 같아야 하며 상태가 섞이면 partial이다. 요약은 항목별 성공/보완/실패 건수와 같은 정수여야 하고 체크값이나 공백뿐인 성공 경로는 거절한다. 모순된 응답은 저장 완료로 승인하지 않으며 기존 요청 ID/자료로 재확인한다.

검증은 기존 예시 서식의 화면/DB 입력으로 실제 생성한 HWPX의 재파싱 내용 일치, 원천 값 보존, 미선택 행 제외, Helper DB 무변경, 누락·중첩·중복 클릭·미실행·저장 충돌을 확인한다. 합성 검증과 실제 업무 서식 인수, 실제 설치된 브라우저 확장/Native 경로는 각각 구분한다. 원본 HWPX Studio와 vendor 스냅샷은 수정하지 않는다.

## 문서 생성 값 규칙 (2026-10-08 사용자 지시, #34)

2026-10-09 지시 2번으로 바뀐 점(#42, 사용자 원문 아님): “화면과 DB가 다릅니다”(화면대로/DB대로)는 묻지 않고 화면 값을 반영해 수집한 뒤 만든다. 바뀐 칸은 생성 창에 알린다. 수집할 수 없는 화면과 파일로 연 자료는 문서로 만들지 않는다(파일은 보기 전용). 정정값 항목은 없앴다(다음 절). 새 차수 이어받기·저장 실패 시 중단·DB 표 미저장 수정 먼저 저장은 그대로다.

사용자 원문(2026-10-08, 사이드 채팅 결정, “내 지시로 처리. 내 원문으로 MVP·이슈에 기록”):

> 1. 문서 생성 값 규칙 (별도 이슈·PR)
> - 원칙: 문서는 항상 DB에 저장된 값으로 만든다. 리모컨 '문서', 추출 표, DB 표 모두 같은 규칙이다.
> - DB에 같은 계약·같은 차수가 있을 때: 화면 값과 DB 값을 비교해 다르면 출력 전에 "화면과 DB가 다릅니다" 묻는다.
>   1) 화면대로 → 화면 값으로 DB를 먼저 덮어쓴 뒤 DB대로 만든다(덮어쓰기는 기존 수집 흐름을 거친다)
>   2) DB대로 → DB 값으로 만든다, DB는 그대로
>   같으면 묻지 않고 바로 만든다.
> - DB에 없을 때(처음 보는 계약, 새 차수): 먼저 수집해서 DB에 넣은 뒤 DB대로 만든다.
>   - 새 차수를 수집할 때 원천 값은 새 화면 값을 쓰고, 사용자 열 값은 이전 차수에서 가져온다.
>   - 가져왔으면 "이전 차수의 사용자 열 값을 가져왔습니다"라고 한 번 알린다.
>   - 이전 차수 자료는 지우지 않는다.
> - 수집할 수 없는 화면(수집 범위 밖 화면, 파일로 연 자료): 화면 값으로 만든다.
> - DB 표에서 고치고 저장 안 한 채 생성하면: 고친 값을 먼저 저장하고 저장된 DB 값으로 만든다.
> - 저장이나 수집이 실패하면 문서를 만들지 않는다.
> - 정정값(d680ac2 정정값 기능을 별도 이슈·PR로 가져온다):
>   - 용어: 당초값 = 마지막으로 수집한 나라장터 값, 정정값 = 내가 DB에서 고친 값, 화면값 = 지금 나라장터 화면 값.
>   - 고친 칸에서 화면값이 당초값과 같으면 묻지 않고 정정값을 유지한다(문서에도 정정값).
>   - 고친 칸에서 화면값이 당초값과 다르면 확인창: 1) 정정값 유지 2) 새 화면값 사용(정정 해제).
>   - 안 고친 칸은 위 규칙대로 "화면대로/DB대로"를 묻고, 고친 칸은 이 비교에서 "다르다"로 세지 않는다.
>   - 이 규칙은 재수집과 문서 생성의 덮어쓰기에 똑같이 적용한다. d680ac2에서 '신규값 반영'을 골라도 정정값이 남던 동작은 이 규칙에 맞게 고친다.

구현 범위 설명(#34, 사용자 원문 아님):
- 정정값 규칙은 원문대로 별도 이슈·PR로 한다. 이 절의 구현에는 넣지 않았다.

  - 고친 값을 먼저 저장하고 저장된 DB 값으로 만든다.
  - 저장이 실패하면 만들지 않는다.
- 새 차수
  - 저장할 때 같은 업무·같은 업무번호에서 휴지통에 없는 더 작은 차수 중 가장 큰 차수의 사용자 열 값을 모두 가져온다. 숫자 차수는 숫자로 비교하고, 숫자가 아닌 차수는 숫자 차수 뒤에 글자 순으로 둔다.

    - 2026-10-09 지시 1번으로 대체(#41): 다섯 열이 없어져 사용자 열 값만 가져온다. 아래 “자동 합계뿐이고 …” 경우도 더는 없다.
  - 가져온 값이 있으면 다음처럼 한 번 알린다(종결 체크도 함께 넘어온다). 기본값뿐이거나, 자동 합계뿐이고 새 차수의 물품으로 다시 계산되는 경우는 가져온 값으로 세지 않는다.
    - 수집: DB 화면 상태줄
    - 문서 출력: 생성 창
  - 한 번에 같은 번호의 여러 차수를 처음 수집하면, 같은 요청 안의 앞 차수는 아직 DB에 없으므로 가져오지 않는다.

>     - 비교할 안:
>       - B: 업무별 메인 + 업무마다 표별 DB 테이블 + 원본
>       - C: 업무별 메인 + 업무별 종속 DB 테이블(1건 1행, 컬럼 = 표 이름, 칸 = 그 표 JSON). 필요한 값만 조인·가공해 메인 화면에 보임 + 원본
>       - 혼합: 메인 / 물품 / 연락처(짬통 포함 여부) / 짬통(그 밖의 표를 표 이름별 JSON) / 원본(중복 제거, 필요할 때만 읽기)
