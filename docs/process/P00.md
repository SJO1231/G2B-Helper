## G01 로컬 Git 기록 준비 (2026-10-02)

사용자의 “근데 왜 깃에는 커밋안하니?”에 따라 로컬 커밋을 준비한다. 기존 지침의 자동 commit/push 금지 때문에 앞선 구현 단계에서는 커밋하지 않았고, 저장소에는 아직 HEAD가 없다. 첫 기록은 현재 MVP와 실행에 필요한 기존 프로젝트 소스·문서·테스트를 기준선으로 포함한다. 참고자료, 기존 prototype, 사용자 DB, 생성 산출물 및 로컬 하네스 상태는 포함하지 않는다. 기존 인덱스는 비어 있음을 확인했다. Git 작성자 이름과 이메일은 미설정이며 사용자에게 요청했다. 원격 저장소 등록·push·전역 Git 설정 변경은 수행하지 않는다. F05 실제 최종 결과는 TypeScript 105, Native 45, UI 26, 피드백 UI 15 검사 통과 및 ZIP 71개 항목 CRC/파일 대응 검증 완료다. 앞선 실행 상태는 이력으로 보존한다.

## 현재 실행 계약

F09에서 하네스 26·기능 106·기존 브라우저 26·피드백 브라우저 22 검사는 통과했다. mvp-package는 등록 output인 dist/mvp-host/install-mvp-host.ps1이 task scope에서 빠져 실행 전에 거부됐다. 제품 소스 오류나 패키지 실행 성공으로 표시하지 않는다. F10은 이 생성 스크립트 한 경로를 추가한 최종 패키징 전환이며 기존 Native 실행 파일·DB 범위는 넓히지 않는다. A04는 같은 제품 빌드의 A03 전후 측정 근거를 보존하고 최종 계약의 하네스·기능 반례를 재확인한다. F09/A03의 실패·통과 이력과 기준선은 보존한다.

Astra A03 실제 수정 후 측정은 빌드 889a2237f1ea225469f6b4bd49429794fbcbc330fb607e5135d8bf0b1aadfddd 기준이다. 1,000행·40열 동작별 3회 중앙값: DB 열기 2,886→274.4ms, 접수 2,480.5→227.5ms, 공고 2,618.2→201.3ms, 계약 2,874.3→225.5ms. 24행 열기는 128→133.6ms로 개선을 주장하지 않는다. 5,000행·60열 같은 조건의 단회 비교는 DB 열기 28,785.6→613.1ms, 접수 26,105.7→555.3ms이며 반복 중앙값과 구분한다. 원본 값 보존·선택·탭 응답 역전 검사 통과 및 미처리 브라우저 오류 0을 확인했다. 실제 DB/Native/IME/활성 hook 검증은 이 결과에 포함하지 않는다.

F09/A03은 F08/A02에서 재현한 오류의 수정본 검증 전환이다. 하네스는 명시한 verificationInputs가 결과 디렉터리 제외보다 우선하도록 하여 검사 스크립트·읽기 전용 제품 변경 후 이전 통과를 stale 처리한다. dispatchModel은 인간 요청 authorizationRef가 명시된 task에만 사용할 수 있으며 실제 hook 모델 대조에 반영한다. 자동 Astra role 차단은 유지한다. 재현 검사 추가 전 24개 통과, 추가 후 24/26·2개 실패, 수정 후 26/26 통과를 구분하며 현재 세션의 hook 실제 로딩은 여전히 미검증이다.

합성 DB 성능 기준은 24행과 1,000행·40열 각각 동작별 3회 중앙값이다. 1,000행 DB 열기 2,886ms, 탭 전환 2,481–2,874ms였고 메모리 RPC는 약 9–10ms였다. 5,000행·60열은 단회 DB 열기 28,786ms/접수 전환 26,106ms로 중간값 근거가 아니다. 열마다 전체 rows decode, 개수 표시의 전체 decode 및 날짜 판정의 불필요한 RecordView 투영을 제거했다. 40행·24열 초기 복제 23,043회로 실패한 성능 회귀 검사는 수정 후 기능 106/106과 함께 통과했다. 빠른 접수→공고 전환에서 공고 활성 탭에 접수 응답이 남는 반례를 재현했고 요청 순번·마지막 응답 반영 및 로딩 중 기존 표 편집 차단으로 수정했다. 최종 전후 측정·오류 재검사는 artifacts/mvp-ui/astra-harness의 build별 결과와 보고서를 기준으로 한다.

F05 최종 검증은 실행 중인 기존 Native Host가 libcrypto-3.dll을 잠근 상태를 확인한 뒤 새 빌드를 dist/mvp-host/feedback에 격리하는 전환이다. F01의 기존 패키징 실패와 F02–F04 검증 이력은 보존한다. 이전 ZIP에서 삭제된 보조 파일 43개만 복구하고 기존 파일·실행 프로세스·사용자 DB는 덮어쓰지 않는다. 새 ZIP의 표준 경로에는 별도 새 빌드가 들어간다. 실제 Chrome 연결은 이번 검토용 메모리 통신 및 임시 DB 검증과 구분한다. 사용자 지시로 Impeccable을 참조했으며 등록되지 않은 맥락 로더는 거부되어 기존 PRODUCT/DESIGN과 지침을 직접 읽었다.

중간 실제 확인: 기존 호스트 62개 파일이 이전 ZIP과 바이트 일치하고 사용 중인 호스트 프로세스가 유지됐다. 새 호스트 빌드는 별도 위치에서 성공했다.
