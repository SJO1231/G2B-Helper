## 이번 구현과 검증

- 추출/판별, Grid, 메인/Bridge, SQLite Gateway, Native Host를 공개 계약으로 조립했다. 원본 참고자료와 기존 두 시안은 수정하지 않았다.
- 납품기한 원천 `dlvgdsTermYmd`를 기준으로 지체일수를 계산하며 미종결금액은 Decimal로 계산한다. 두 값은 읽기 전용이다. 종결은 계약에만, 사용자 열 표시/숨김은 세 업무에 공통이다.
- 사용자 이름이 원천 이름·원본 JSON·물품 표 이름과 같아도 소유별 매핑을 유지한다. 화면 별칭을 원천/사용자 레코드로 저장하지 않는다. 정의 삭제는 저장값 삭제와 구분한다.
- TypeScript 88개 검사: 추출 20, Bridge 17, Grid 25, 계약 계산 16, 화면/저장 소유권 10. 31개 로컬 data_map 파일의 전체 표·행·원본 대응을 원문 복제 없이 검사한다.
- Native 39개 검사: 부분 병합, 승인 충돌, 저장 버전, 전부 롤백, 요청 재시도, 사용자 열 정의 CAS, 프레이밍/큰 응답, 재시작. 패키지 exe를 한글·공백 경로에서 별도 임시 DB로 실행하는 검사도 포함한다.
- Playwright 26개 검사: 실제 설치 Chrome의 격리 컨텍스트에서 Grid·라이트/다크·편집/취소/선택/필터/열 이동·출력·계약 계산·리모컨 DOM 확인. 합성 자료와 제공 JSON 확인을 분리한다. 위젯 통신은 mock이며 실제 확장 주입 검증으로 세지 않는다.
- 캡처: `artifacts/mvp-ui/01-extract-light.png`, `02-extract-dark.png`, `03-contract-light.png`, `04-widget-light.png`, `05-widget-dark.png`. 최신 실행 증거에는 빌드 해시·브라우저 오류·검사 결과가 포함된다.
- 권장 통합 모델은 `gpt-6.1-sol / xhigh`, 실제 담당 구현·독립 검토는 `gpt-6.1-sol / high`. Astra는 사용하지 않았다.

## 미검증·검토 사항과 다음 순서

1. 패키지의 `설치안내.txt`대로 확장을 로드하고 표시되는 확장 ID로 Native Host를 등록한다. 개발 중 사용자 Chrome/Edge 프로필과 레지스트리에 등록하지 않았다.
2. 실제 접수·입찰·계약 화면에서 수집/추출, ±1년/조회/엑셀/건수, frame 접근과 로딩 상태, 재조회, 스크립트 활성화 및 단축키를 확인한다. 저장 샘플·격리 브라우저 검사만으로 이 단계를 통과 처리하지 않는다.
3. 사용자 열 삭제는 정의만 제거하고 저장값은 보존하는 설계 기본값이다. 영구 삭제·복원 UI가 필요하면 별도 확정 후 구현한다. 페이지 위젯 단축키와 Chrome/Edge 전체 단축키 설정을 구분한다.
4. 사용자 피드백 이후에 다음 기능 공정을 정한다. 이번 결과를 기존 전체 제품 완료로 간주하지 않는다. GitHub 게시 방식은 답변 대기이며 현재 로컬 산출물만 제공한다.
