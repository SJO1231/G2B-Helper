# G2B Helper — 현재 MVP 기준 (2026-10-02)

최신 근거는 사용자 첨부 `0b2ba2aa-4f8c-4620-ad4c-8d580ef6dc26/붙여넣은 텍스트.txt`와 후속 답변이다. 기존 전체 제품 요구는 PRODUCT.md에 보존하며 이번 단계에서 삭제하지 않는다. 승인된 하네스는 P00, 현재 MVP 작업은 M01에 기록한다.

## 확정과 정정

- Chrome/Edge MV3, 작은 이동형 리모컨·원형 접기·페이지 안 Grid. 닫기는 종료, 확장 아이콘으로 재실행.
- 수동 추출은 현재 로딩 자료를 임시 Grid로만 표시한다. 수집은 지정 URL+areaCd+depth1+depth2(+존재하는 depth3)와 업무키를 검사한 뒤 비교·저장한다.
- 후속 사용자 지시: `참고자료/js.txt`의 WebSquare gridView → DataList.getAllJSON 방식이 추출 기준이다. 기본 추출 표는 `tables`만, 설정의 전체/테이블 선택으로 `pointInfo`도 표시할 수 있다. pointInfo는 표시 설정과 무관하게 원본과 화면 판별에 유지한다. 빈 표도 삭제하지 않는다.
- SQLite Gateway 사용은 사용자 답변으로 재확정했다. 첨부의 IndexedDB 폴더/흐름과 SQLite 제외 문구는 이번 구현에서 적용하지 않는다. 브라우저 데이터 저장소로 우회하지 않는다.
- 상세 중복 규칙을 따른다: 신규 저장, 동일 유지, 기존 빈값 자동 보충, 충돌은 간단한 필드 선택창. 영구 변경이력/복잡한 DIFF 시스템은 보류한다.
- SON 원문은 문맥상 JSON 원문으로 해석한다. 원천 key 변경 없이 표시명만 사전에 저장한다. 사용자 열은 원본과 별도 저장한다.
- 저장 안전성을 위한 구현 기본값: 사용자 열 삭제는 정의만 제거하고 기존 저장값을 보존한다. 필터 밖 행에서 삭제한 정의를 다시 생성하지 않는다. 영구 삭제·삭제한 열 복원 UI는 보류한다. 이는 사용자 원문의 확정 동작과 구분하는 설계 기본값이다.
- 후속 확정: 설정에서 다섯 실행 단축키를 지정(수집 Alt+Shift+S, 문서 연결 Alt+Shift+D 기본), 리모컨은 ±1년 버튼만 두고 Grid는 날짜 구간과 ±1년 필터를 함께 둔다. 돈·날짜·텍스트 열 타입은 원값을 바꾸지 않고 표시·입력 검사를 담당한다.
- 계약만: 종결 사용자 체크열/독립 필터, 지정일, 지체일수(지정일−납품기한), 종결금액, 미종결금액(계약금액−종결금액), 선금보증기한/금액. 파생 두 열은 읽기 계산값이며 빈 종결금액은 계산에서 0으로 해석하고 입력 자체는 빈값을 유지한다. 전 업무 공통으로 사용자 열 숨김/해제 버튼을 제공한다.
- 자동수집·자동 클릭/탐색 기능, 문서/HWPX, 탐색기, 메모·일정, AI/Jev, 복잡한 관계·정규화는 제품에서 제외한다. Playwright는 제품에 넣지 않고 개발 검증에 사용 가능하다는 후속 사용자 정정을 따른다. 수동으로 누른 업무 보조 버튼만 페이지에 명령을 전달한다.

원본·raw JSON·0/false·정확한 decimal·모든 추출 표는 표시 숨김과 무관하게 유지한다. 수집 규칙이 미설정이면 기존 지정 화면 검사를 유지한다. 사용자 규칙을 켜면 명시적 조건 목록을 사용하고 빈 목록은 수집을 허용하지 않는다. 어느 경우에도 G2B 출처 검사와 업무키·동일 frame 검사는 유지한다. 휴지통의 업무키를 다시 수집하거나 편집하려면 먼저 복원한다. 삭제·복원과 설정 저장은 버전 검사 및 동일 요청 재시도 안전성을 따른다.

## 추가 Comment 1–13 및 후속 답변 (2026-10-02)

설정 첫 탭은 일반이며 DB 휴지통을 이곳으로 이동한다. 종결은 사용자 열 숨김 옆, 원본 JSON은 JSON 옆으로 옮기고 기간과 내보내기를 공통 도구 줄로 합친다. 추출은 DB와 같은 배치·기간 제어를 사용하되 기존 원본 표 탭과 임시 편집, 저장 버튼 제거를 유지한다. 추출의 기간 필터는 표시만 바꾸며 숨겨진 행·수정 내용·원본 JSON을 삭제하지 않는다. 사용자 열은 원본 미매핑/빈 값 분류에서 제외한다. 열 분류 설명 문구는 제거하고 접기·펼치기를 제공한다. 별도 완전 일치 입력은 값 목록 검색·선택으로 통합하고 포함/제외 검색은 유지한다. 안내는 짧게 표시하며 전체 문장은 title로 확인한다. 런처 편집 설정 버튼을 제거하고 리모컨의 저장 런처와 추가 버튼은 늘 4열로 배치한다. 청록 활성 상태와 파랑 선택색에 한정한 색상 포인트를 밝음/어두움 테마에 적용한다. 사용자 지시로 Astra의 독립 기능 점검을 수행하고 실제 나라장터/Native 미검증 범위는 구분한다. 지정 GitHub 저장소는 SJO1231/G2B-Helper다.

## 구현 구조

2026-10-03 Comment 1–15 및 후속 정정: 제목줄은 심플하게 유지한다. 행·열 정보와 안내는 하단 한 줄에서 함께 표시하며 빈 안내줄을 따로 두지 않는다. 기간 입력은 92px로 줄인다. 표 위의 별도 도구줄·AND/OR 선택·사용자 열 추가 버튼은 제거하고 열 필터는 항상 모든 열 조건을 함께 충족해야 한다. 이전 OR 보기 상태도 AND로 복원한다. ‘속성’ 토글은 표 왼쪽 위 행 번호 머리글에 두며 열 표시/숨김과 사용자 열 추가는 이 안에서 제공한다. 열 필터 해제는 사용자 열 숨김 옆으로 옮긴다. 런처 단축키는 런처 추가창 하나를 열며 저장한 개별 스크립트는 리모컨 버튼으로 실행한다. 수집 기본 조건은 제공 자료의 pointInfo 화면 코드에 근거하며 현재 나라장터와 일치하는지는 별도 확인 대상이다. 기본 조건 사용을 해제하면 사용자 조건을 편집하며 이번 설정창에서 기본/사용자 조건과 탭을 전환해도 작성 중인 사용자 조건을 보존한다. 기본 조건을 저장한 뒤 재개하는 창에는 기본값이 적용된다. 계약 계산 열은 미종결금액=계약금액−종결금액, 지체일수=지정일−납품기한이며 키 사전에 식을 안내한다. 자유 계산식 편집은 이번 승인에 포함하지 않는다.

추가 화면 주석 1–25: 기능창·대화창 제목줄은 리모컨과 같은 34px 높이로 맞추며 설정/닫기/저장/열 분류 접기는 SVG 아이콘과 접근 가능한 이름을 사용한다. 추출의 저장 버튼은 표시하되 비활성으로 유지한다. 기간 기준은 날짜·날짜시간으로 지정한 열만 포함한다. 종결 버튼은 선택한 계약 행의 사용자 종결 체크값을 반전하며 사용자 열 숨김 앞에 둔다. 열 목록 우클릭으로 키 사전을 추가하고, 선택한 여러 열을 묶음 이동/숨김하며 Ctrl+Z로 되돌린다. 숨김 열 버튼은 토글이다. 하단 오른쪽에 행 수·표시/전체 열 수를 작게 표시한다. 값 사전은 표시명과 원천 키를 함께 보여주며 선택 셀의 서로 다른 키/값을 한 창에서 일괄 설정한다. 저장은 우측 아이콘으로 제공하고 설정창에서는 닫기 옆에 둔다. 설정 탭의 시작 위치와 크기는 일정하다. − 버튼의 위치에 원형으로 접히고 ×는 종료한다.

## Studio lite 생성 연결 (2026-10-03 사용자 승인)

이 절은 앞의 문서/HWPX 제외 범위 중 지정 서식 생성 연결만 대체한다. 업무 DB와 선택 자료는 Helper가 소유하고, 서식·원천 키 Column 매핑·문구 조건·파일 생성은 Studio lite가 소유한다. Helper가 DB에 먼저 저장하도록 강제하거나 Studio가 Helper DB를 직접 쓰지 않는다. 개인 분석기, DocWeave, 신규 수집 표, 관계 편집, 트레이·전역 단축키, 설치 통합은 이번에 추가하지 않는다.

Studio lite에서 저장한 프로젝트 revision과 출력 폴더를 생성 프로필 ID에 연결한다. Helper의 문서 연결 설정은 업무별 프로필 ID만 저장한다. 표시명 사전은 문서 매핑에 사용하지 않는다. 리모컨 문서는 현재 화면 인식 → 간단한 자료 선택창 → 연결된 서식으로 파일 저장이다. 화면 규칙/업무키로 인식한 자료만 후보로 쓰고 하위 표·출처를 보존한다. 매칭 자료가 없으면 DB로 연결하며 읽기 오류는 자료 없음과 구분해 알린다. DB나 추출 표에서 선택한 행의 생성도 같은 선택창을 사용한다. 선택창은 자료별 체크와 이미 연결된 서식을 표시하며 100건 초과 후보는 자동 선택하지 않는다. 문구 조건은 기존 Studio 서식이 소유하고 별도의 임의 조건 편집기는 추가하지 않는다. 정상 연결이면 서식 선택창·Studio 제작기를 매번 열지 않는다. 연결이 없을 때만 서식을 지정하며 누락·충돌·지원하지 않는 자료는 항목별 보완 사유로 표시한다.

첫 연결은 1~100개 선택 행과 단일 값 서식이다. 원천 필드·사용자 값·출처·업무 식별값을 구분해서 전달하고 선행 0·정밀 금액 문자열·0·false·빈값을 유지한다. 빈 하위 표는 허용하고 실제 하위 행이나 중첩 값은 누락시키지 않고 생성 보완 대상으로 돌린다. Studio의 기존 money 형식이 정확히 처리할 수 없는 소수·큰 금액은 문자 매핑을 사용하며 안전한 정수 원 금액만 money로 허용한다. Helper 표의 읽기 계산 열은 원천 필드에 섞지 않는다.

Native는 고정 loopback 주소의 Studio 경로로 요청 ID·출처·프로필 ID·자료를 보내며, Studio는 프로젝트/출력 계획과 항목별 결과를 저장한다. 같은 요청의 재시도는 같은 파일을 확인하고 다른 입력에 같은 ID를 재사용하면 거절한다. 기존 파일은 같은 해시인 경우만 재사용하며 다른 파일은 덮어쓰지 않는다. 파일 저장 완료·보완 필요·실패를 구분하고 자동 열기/인쇄는 하지 않는다. 진행 중에는 생성창 닫기를 막고, 통신 결과를 확인하지 못하면 열린 Helper 화면에서 같은 요청으로 재확인한다.

Native는 생성 응답의 항목 수·번호·상태와 성공 파일 경로, 전체 상태 및 요약 건수의 일치를 확인한다. 같은 항목 상태만 있으면 전체 상태도 같아야 하며 상태가 섞이면 partial이다. 요약은 항목별 성공/보완/실패 건수와 같은 정수여야 하고 체크값이나 공백뿐인 성공 경로는 거절한다. 모순된 응답은 저장 완료로 승인하지 않으며 기존 요청 ID/자료로 재확인한다.

검증은 기존 예시 서식의 화면/DB 입력으로 실제 생성한 HWPX의 재파싱 내용 일치, 원천 값 보존, 미선택 행 제외, Helper DB 무변경, 누락·중첩·중복 클릭·미실행·저장 충돌을 확인한다. 합성 검증과 실제 업무 서식 인수, 실제 설치된 브라우저 확장/Native 경로는 각각 구분한다. 원본 HWPX Studio와 vendor 스냅샷은 수정하지 않는다.

## 공유 설정·정정값·저장 복구·설치 보완 (2026-10-03 사용자 승인)

설정창에서 저장이 거절되면 작성 중인 초안은 유지해 재시도할 수 있게 한다. 저장 중에는 닫기·Escape와 추가 설정 입력을 막는다. 앞의 마지막 저장 설정으로 화면을 복원하는 동작은 표에서 수행한 설정 자동 저장의 실패에 적용한다. DB 행 저장 중에는 추가 셀 편집·업무 전환을 막아 전송한 값과 사용자 입력이 어긋나지 않게 한다.

설정창 초안은 앞선 표 설정 자동 저장 큐가 확정/거절된 뒤 시작한다. 기다리는 동안 설정 버튼의 반복 진입을 막고 그 사이 추가된 자동 저장도 처리한다. 앞선 자동 저장이 실패했어도 마지막 확정 설정을 편집할 수 있으며, 닫기는 초안 취소만 하고 새 저장이나 대기를 추가하지 않는다.

공유 설정은 설정창의 공유 설정 탭에서 JSON 파일로 내보내고 가져온다. 키/값 사전, 열 타입·서식·잠금, 수집 화면 조건만 포함한다. 실행 JS·런처, 단축키·테마·개인 경로, Studio 프로필 연결과 업무 자료는 공유하지 않는다. 가져오기 전에 형식·버전·용량·필수 조건을 검사하고 현재 값과 적용 값을 표시한다. 충돌 기본값은 현재 유지이며 사용자가 선택한 변경만 설정 초안에 적용한다. 설정창 저장으로 확정하고 닫기로 취소한다. 최대 10건/총 3MB 이력에서 되돌리기를 미리 볼 수 있으며 이후 변경한 로컬 값과의 충돌도 선택한다. 이 검사는 실제 나라장터 화면의 유효성 확인을 대신하지 않는다.

DB 자료의 fields는 기존 소비자에게 제공하는 유효값이다. sourceFields는 최근 승인한 수집값, overrides는 사용자 정정값을 보관하며 사용자 열과 구분한다. 재수집은 sourceFields와 비교하고 정정값은 유지한다. 정정한 셀의 작은 정정 표시와 우클릭 메뉴에서 수집값/정정값을 보고 정정 취소할 수 있다. 정정 취소는 최신 수집값으로 돌아가며 버전·잠금·식별키 제약을 적용한다. 기존 기록에 메타데이터가 없으면 현재 저장값을 기준으로 삼고 과거 원본에서 편집 이전 값을 추측하지 않는다. 표 저장 중 추가 편집을 막으며 설정 저장 중 닫기·Escape를 막는다. 설정 저장 거절 시 표시는 확정 설정으로 복구하되 대화창 작성 초안은 재시도할 수 있도록 유지한다.

DB/설정 쓰기 요청은 전송 전에 확장 storage.session에 미확인 요청 한 건을 보관한다. 다른 기능창과 service worker 재시작에서도 같은 요청을 찾으며, 저장 결과 확인은 Native의 기존 요청 결과를 먼저 조회한다. 저장 기록이 없을 때만 같은 ID/본문을 재전송하고 다른 새 쓰기는 먼저 미확인 건을 처리해야 한다. 확정 결과 뒤 임시 요청은 제거한다. 임시 보관 실패·8MB 초과는 쓰기 전에 거절한다. 이는 업무 DB의 대체 저장소가 아니며 브라우저 종료·확장 비활성화/재로드/업데이트 시 세션이 지워지는 한계가 있다. Studio 문서 생성의 별도 요청 처리 계약은 유지한다. Native 쓰기 요청 캐시는 SQLite 쓰기 잠금을 얻은 뒤 검사하여 동시 재시도에서도 1회만 반영한다.

설치 스크립트는 Chrome/Edge 확장 ID를 한 번에 받아 두 브라우저의 사용자 Native 등록을 함께 준비한다. 기존 유효한 허용 ID는 보존한다. 확장 ID 자체를 바꾸지 않으며 잘못된 ID·실행 파일·손상 manifest는 변경 전 거절한다. manifest는 임시 작성 후 교체하고 Preview는 변경 없이 확인한다. 최초 브라우저 확장 로드는 사용자가 수행하며 개발 검사는 실제 사용자 레지스트리·운영 DB를 변경하지 않는다.

## 메모·화면·관계의 후속 설계 (구현 아님)

2026-10-03 사용자는 메모를 후속으로 두고 화면·관계도 설계까지만 확정했다. 현재 MVP에는 독립 메모 기능이 없다. 일반 사용자 열에 메모라는 이름을 붙일 수 있는 것과 메모 기능 구현은 구분한다.

- 메모 본문은 별도 notes 테이블에 한 번 보관하고 대상 연결은 note_links로 분리한다. 일반 메모는 연결 대상 없음, 화면고정은 screenId, 업무고정은 업무 종류와 안정적인 업무키를 사용한다. 화면 좌표 고정 여부는 연결 대상과 별도 UI 속성이다. 업무 전체에 붙는 메모는 변경차수와 분리하며 특정 차수에 붙일 때만 차수를 포함한다. 조회할 때 연결을 조인하고 본문을 업무 행마다 복제하지 않는다. 한 화면/업무에 여러 메모가 있어도 기존 표 행이 중복되지 않도록 메모 목록은 별도 조회하거나 집계한다.
- 화면 정의는 screenId, 이름, URL 패턴, areaCd/depth1/depth2/depth3, 업무 종류를 소유한다. 프레임은 실행 시 실제 출처로 검증하며 화면 ID를 URL 전체/세션 값/표시 제목으로 만들지 않는다. 기존 수집 조건과 별도 중복 정본을 만들지 않고 향후 화면 정의로 통합한다. 빈 depth3의 모든 하위 화면 허용 의미와 정확한 화면 고정은 구분한다.
- 관계 정의는 양쪽 자료 종류·원천 키 쌍·1:1/1:N 조건을 보관한다. 실제 연결의 확정/거절은 별도 결정 기록에 보관하며 후보 일치를 사용자 승인이라고 부르지 않는다. 복합 식별키는 선행 0·차수와 타입을 보존한다. 자동 후보는 원천값 기준을 기본 제안으로 두되 확정되지 않은 설계이며, 정정값 변경이 확정 관계를 자동 변경하지 않도록 한다.
- 레거시의 필드 쌍 검사·관계 미리보기 토큰·화면 단위 필터·참조 검사 원칙은 재사용 후보다. 관계 중첩 루프, Python False==0 비교, depth3 누락과 URL만으로 모든 업무 화면을 같은 메모 대상으로 취급하는 부분은 그대로 복사하지 않는다. 관계 후보 조회는 복합키 인덱스/조인으로 개선하고 화면/관계 등록이 새 데이터셋 생성까지 자동 확장되지 않도록 한다.

백업·복원, 미확인 요청의 브라우저 재시작 후 영속 복구, 범용 관계 편집 UI, 메모 UI, 설치 프로그램 통합은 이번 구현에 포함하지 않았다.

## 설치 실행 정정 (2026-10-03 후속 요청)

위의 설치 프로그램 통합 보류와 별개로, ID 입력과 PowerShell 수동 실행을 없애는 설치 실행 파일은 이번에 제공한다. 일반 Windows PC의 Chrome·Edge에서 자체 로컬 스토어 페이지를 만드는 것으로 공식 스토어의 설치 권한을 얻지는 못한다. 사내 관리 정책 배포는 별도 관리자 환경과 배포 계약이 필요한 후속 방식이다. 이번에는 브라우저 정책/프로필을 바꾸지 않고 최초 압축해제 확장 추가만 사용자가 수행한다. 설치.cmd는 Native 등록 완료와 브라우저 확장 추가를 구분해 안내하며 실행 제한 오류를 완료로 표시하지 않는다.
