# G2B Helper 공통 Agent 지침

현재 실행 기준은 최신 첨부 요구를 정리한 `docs/MVP.md`와 승인·명령·상태를 소유하는 `docs/process/P00.md`다. 이전 PCE 순차 리뷰·자동수집·통합 계획은 이번 MVP에서 보류했다. 원본과 기존 prototype을 보존하며 보류를 승인·완료로 표현하지 않는다.

## 네 원칙

1. 코딩 전에 목표·가정·현재 구현·기존 변경을 확인한다. 결과를 바꾸는 모호함을 드러내고, 사소한 되돌릴 수 있는 선택은 승인 범위에서 판단한다.
2. 승인된 문제를 해결하는 최소 구현을 택한다. 새 framework·원장·서비스나 미래 기능을 추가하지 않는다.
3. 필요한 파일만 고친다. 사용자·다른 Agent 변경을 보존하고 자신의 변경만 정리한다. `참고자료/**`, `prototypes/**`와 P00의 frozen은 수정하지 않는다. `E:/Prodev/HWPX Studio`는 읽기 전용 참고다.
4. 성공 조건을 실제 실행·산출물로 검증한다. 실패·대상 0건·준비 오류·미실행을 통과로 세지 않는다. 작성·설정·실제 로딩·런타임·사용자 수용을 구별한다.

## 작업 라우팅과 경계

- 작업 전·범위 변경/인계 때·완료 전에 최신 사용자 지시와 해당 MVP/P00 절을 대조한다. 원문과 확정 요구를 삭제·축약·병합·재해석하지 않는다. 요약은 원문 위치·생략 범위를 가진 별도 산출물이며 원문을 대체하지 않는다.
- 편집 전 P00의 변경 계약에 요구 ID·원문 위치·기준 원본·보존 기능/UI·허용 변경을 연결한다. 사용자 요청/확정·AI 제안·미결정을 구분하고, 미확인 원본을 추측으로 채우지 않는다. 상세 절차는 `.agents/hooks/README.md`의 요구보존 게이트다.
- 삭제·기능 축소·요구 병합·의미/완료 기준 변경·문서 전면 재작성은 대상·이유·영향·대안을 먼저 제시하고 명시적 승인을 받는다. 샘플 허용·별도 사본·레거시 참고·위임은 새 기능/업무 버튼/배치 변경의 승인이 아니다.
- 구현 대체 전 기존 기능·예외·검사의 대응표를 작성한다. 요청 범위 밖 정리는 별도 제안하며, 이전 제품/시안/결정은 덮어쓰지 않고 변경 이유와 대체 위치를 연결해 보관한다.
- 작업 후 요구별 유지/변경/추가/삭제 제안/미구현을 대조한다. 원본 파일 hash·기존 동작·UI 배치·요구 충족을 따로 검사한다. 누락·의미 변경·필수 미검증이 있으면 완료가 아니며, 검사 통과와 사용자 수용도 구분한다.
- 중요한 UI/동작/소유 변경은 구현자와 다른 read-only verifier가 원문·원본·diff·실제 화면/근거를 대조한다. 단순 문구 등 작은 작업은 P00에 독립 검토 비해당 이유를 남긴다. 총괄이 실제 변경과 판정을 확인하며 hook은 자연어 판단을 대신하지 않는다.

- 새 작업은 P00의 approved task와 역할 경계 안에서 진행한다. `node scripts/harness/cli.mjs doctor`, `start TASK ROLE`, `guard TASK ROLE PATH...`, `run TASK ROLE COMMAND_ID`, `verify TASK ROLE`를 사용한다. 세부 계약은 `.agents/hooks/README.md`.
- 공통 Node 검사기는 P00의 `harness-json` 하나를 읽는다. 파일 mutation은 알려진 Edit/Write/patch 경로만, shell은 등록 명령 wrapper만 허용한다. 알 수 없는 mutation 도구·명령·우회 권한 옵션은 거부한다.
- 시작 baseline은 미추적 파일도 포함한다. 이미 있는 수정은 시작 상태로 보존하며, baseline은 실행 중 임의 갱신하지 않는다. 새 승인·task 전환은 인간의 현재 범위를 근거로 P00 갱신 후 새 start 한다.
- 역할 모델·effort는 `.codex/agents/`, `.claude/agents/`에 명시한다. 실제 모델은 실행 관측으로 따로 기록한다. Astra는 자동 호출하지 않는다. 하위 Agent는 재귀 위임하지 않는다.
- fresh context에는 목표·필요한 명세 절·허용 파일·검증·중단 조건만 전달한다. Skill·과거 문서·참고자료 전체를 시작 컨텍스트에 넣지 않는다.
- hooks는 OS 보안 경계가 아니다. unsupported·trust 미승인·skip·timeout·fail-open을 감지하면 실행 보호가 확인되지 않은 상태로 보고한다. 현재 세션에 새 hook이 자동 로딩되었다고 말하지 않는다.
- 프로젝트 전역 권한 승격·사용자 전역 설정 변경·자동 Git commit/push를 하지 않는다. 현재 승인으로 충분한 가역 작업은 반복 승인 질문 없이 진행한다.
- 수동 화면 확인·최신 첨부의 명시적 처리만 MVP 기준이다. 제품의 브라우저 자동화·자동수집 기능은 이번 MVP에서 제외한다. Playwright는 개발 검증에 사용할 수 있다. raw 값, 식별 문자열, decimal, 0/false와 G2B 원천 키를 보존한다.
- 과거 아키텍처가 필요한 기존 코드 유지 작업만 `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, `docs/GLOSSARY.md`, `.agents/rules/extension.md`를 선택해서 읽는다. 최신 MVP와 충돌하는 과거 지침을 활성 계획으로 되살리지 않는다.

## 기존 여섯 Skill

Codex는 `.agents/skills/`, Claude는 `.claude/skills/`에서 필요한 Skill만 읽는다. Windows의 `.Claude`와 `.claude`는 같은 디렉터리다.

- `focused-plan`: 목표·범위·검증 연결
- `root-cause-fix`: 재현·원인·최소 수정
- `verify-change`: 주장·실행 근거·미검증 범위
- `session-handoff`: 기존 P00에 상태·다음 행동
- `review-boundaries`: 정본·소유·계약
- `delegate-bounded-task`: 이미 승인된 위임 경계

새 원장이나 중복 계획 파일을 만들지 않는다. 공정 사실은 P00에, 요구는 MVP.md에 둔다. 비밀값·원문 업무 자료를 로그·공개 fixture로 복제하지 않는다.
