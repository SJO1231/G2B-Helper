## v5 적용 목록

컨트롤(표시/숨김/radio/checkbox/trigger), 원본·정규화 ID, DOM 속성/경로, 컴포넌트 메서드·값·선택 상태, 액션 전후와 사용자/JS 구분, 메뉴 요청/실제 이동, gfnExecute, XHR/fetch 요청/응답, JSON keyPaths, actionId/requestId 연결, 직링크 실행/복사, 검색, Import/Export, 시작/중지/스캔이 원문에 존재한다.

그대로 복사할 결함도 확인했다. v5는 중지 시 hook을 남기고 플래그로 기록만 막는다. raw 네트워크 headers/body를 넓게 저장하고, 비동기 액션·콜백이 중지 뒤 끝날 수 있으며, 전역 함수 복구가 다른 래퍼를 덮을 수 있다. 적용 시 탭·화면 범위 검사, 세대별 중지, 직렬화/용량 제한, 원래 호출 결과 보존과 실패 격리를 검증해야 한다. 저장 원본과 화면 표시를 혼동하지 않는다.

## 순차 작업

1. **이번 확인:** `prototypes/table-flow`의 추출 → 선택 설정 → 저장 분류 → 표 재열기. 사용자에게 실제 시안을 보여주고 확인.
2. **저장 연결:** 선택 화면조건/업무키, 모든 열 보존, 원자적 표·행·선택 규칙 저장, SQL 재조회. 이때 기존 데이터 이관 영향도 별도 제시.
3. **DB 편집:** 열·탭 이동, 우클릭, 명시 Grid 저장, 화면고정과 삭제 차단, 탐색 항목 정리. 관계/사전/수집은 별도 설정 화면.
4. **메모·달력:** 최신 목록/스티커/관리/달력 지시를 한 컴포넌트로 연결. 휴지통 복원 유지.
5. **탐색기·자석 배치:** ExFinder 연계 시안 확인 후 Native 연결. 웹 목록으로 완료 주장 금지.
6. **수집관리:** v5 관찰 기능을 종류별로 연결하고 시작/정지/실패를 검증.

## 설계 제안 — 아직 사용자 승인 아님

- 큰 표는 유지하고 저장 설정은 표 아래에 펼침. 분류/화면조건/업무키 탭으로 앞뒤 이동.
- 헤더 화면은 요청할 때만 열며 원본 키와 표시명을 나란히 표시.
- 업무키 없는 표는 내부 행 ID로 저장. 선택 키가 있으면 중복 검사. 시안은 중복 키를 오류로 알려주며 제품의 필드별 충돌 비교는 아직 연결하지 않음.
- 화면조건 없는 저장은 자동 수집 등록을 의미하지 않음. 나중에 표 설정에서 화면을 지정.
- Tabulator 전체 열 선택을 유지할 때는 **헤더를 클릭해 선택한 뒤 다시 끌면 이동**한다. 첫 드래그는 열 범위를 선택한다. 더 직접적인 드래그를 원할 경우 전용 이동 손잡이 등 대안을 사용자에게 확인.

## 증거의 범위

이번 HTML 시안은 메모리 내 상태만 사용한다. IndexedDB/localStorage, Native Host, 사용자 SQL DB에 쓰지 않는다. 재열기는 시안 내 DB 메뉴에서의 조회이고 프로그램 재시작 후 영속 조회가 아니다. 기존 확장 배포물은 교체하지 않는다. 실제 테스트 결과는 `prototypes/table-flow/evidence/report.json` 참조.

실행 결과: 별도 시안 빌드 성공, 원문 포맷 동일성 확인, Playwright Edge 12개 흐름 통과·페이지 오류/경고 0. 제공 JSON 31개에서 217개 표/화면값 묶음을 변환·복제 후 원본 행 내용과 동일함을 검사했다. 이는 SQL 안정성이나 실제 나라장터 수집 재검증이 아니다.

Tabulator 공식 확인: [열 이동](https://tabulator.info/docs/6.x/move/), [범위 선택](https://tabulator.info/docs/6.x/range/), [우클릭 메뉴](https://tabulator.info/docs/6.x/menu/).

### 시안 댓글 1 반영

사용자 요구: 빈 영역까지 Excel처럼 왼쪽 행 번호 표시. `grid.js`에서 배경선만 있던 빈 영역을 번호가 있는 실제 입력행으로 변경했다. 미입력 행은 결과에서 제외하고 원본 빈 행은 유지한다. Playwright 추가 3건(큰 화면의 번호, 빈 행 입력 유지, 입력 지운 행의 출력 제외)을 포함해 총 15건 통과. `06-numbered-blank-rows.png`는 사용자와 같은 2215×1244 화면에서 확인한 결과다.

설계 구현: `grid-controls.js`로 표시·필터 로직을 분리했다. 표시·필터는 세션 상태이며 저장·JSON 출력에는 전체 원본 행을 유지한다. 중첩 조건 그룹과 동일 열의 여러 조건 블록은 이번 시안에 연결하지 않았으며 기존 상세 필터 요구는 계속 남아 있다. 시스템 조회는 실제 SQLite 시스템 DB 연결을 뜻하지 않는다.

검증: 빌드 및 원본 v4.1 포맷 동일성 검사 성공. 검증 23건(브라우저 동작 22건, 값 자료형 구분 1건), 오류·경고 0. 기존 제공 JSON 31개·217개 표의 복제 후 원본 동일성 검사 통과. 화이트·블랙 열 표시/필터/DB 배치를 캡처로 확인했다. 보고서와 10개 캡처는 `prototypes/table-flow/evidence`에 있다.

추가 발견·수정: 고정 배치만 있는 시안의 body 높이가 실제 0이었고, Tabulator Popup의 부모 높이 계산 때문에 우클릭 메뉴가 화면 위로 밀렸다. body의 최소 높이를 화면 높이로 지정한 뒤 실제 우클릭 → 열 숨김 → 복원을 검증했다. 관련 구현은 설치된 Tabulator의 Popup `_fitToScreen` 코드를 근거로 확인했다.
